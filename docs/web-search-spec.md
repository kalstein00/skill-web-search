## Problem Statement

내부망 PC에서는 인터넷에 직접 접근할 수 없어 Cline이 작업 중 필요한 공개 웹 정보를 검색하거나 페이지 본문을 읽을 수 없다. 사용자는 같은 네트워크의 인터넷 PC를 통해 이 기능을 제공하고 싶다. 인터넷 PC에 Cline이 설치되어 있다는 전제나 유료 검색 API는 사용할 수 없다.

Windows와 Linux의 내부망 PC에서 Cline 스킬을 호출하면 검색 결과와 출처를 얻고, 필요한 페이지를 선택해 읽을 수 있어야 한다. 프로젝트 파일이나 전체 대화를 인터넷 PC에 전달하지 않고 최종 해석은 내부망 Cline이 맡아야 한다.

## Solution

Cline 스킬과 Python 클라이언트, Windows x64용 독립 웹 중계 서버를 제공한다. 내부망 PC는 Cline과 uv가 사전 설치된 환경에서 uv로 미리 준비한 Python 3.12 이상으로 클라이언트를 실행하고, 프로젝트별 환경 설정에서 서버 주소와 공유 토큰을 읽는다.

인터넷 PC에서는 운영자가 서버 실행파일에 수신 주소·포트·공유 토큰을 인자로 전달한다. FastAPI 서버는 함께 배포한 전용 헤드리스 브라우저로 Google 검색을 수행하고 일반 공개 HTML의 본문 조회를 제공한다. 서버에는 Cline이나 별도 Python 설치가 필요하지 않다.

검색과 본문 조회를 독립된 요청으로 제공한다. 클라이언트는 결과를 JSON으로 반환하여 Cline이 출처를 확인하고 후속 조회 여부를 판단할 수 있게 한다. 첫 버전은 사내망 HTTP와 공유 토큰 인증을 사용한다.

## User Stories

1. 내부망 PC 사용자로서, Cline 스킬로 공개 웹을 검색하여 인터넷 직접 접속 없이 필요한 정보를 찾고 싶다.
2. Windows 사용자로서, Python과 uv로 클라이언트를 실행하여 별도 클라이언트 빌드 없이 기능을 사용하고 싶다.
3. Linux 사용자로서, 같은 스킬과 Python 클라이언트를 사용하여 동일한 검색 계약을 이용하고 싶다.
4. 내부망 PC 사용자로서, 사전 준비한 런타임만으로 실행하여 패키지나 Python 다운로드 없이 작업하고 싶다.
5. 프로젝트 사용자로서, 프로젝트별 서버 주소와 공유 토큰을 설정하여 사용할 웹 중계 서버를 지정하고 싶다.
6. 프로젝트 사용자로서, 명시한 프로젝트 루트의 설정만 읽게 하여 다른 프로젝트의 서버나 인증정보가 선택되는 것을 방지하고 싶다.
7. 내부망 PC 사용자로서, 설정 누락을 명확히 안내받아 접속 실패의 원인을 수정하고 싶다.
8. 내부망 PC 사용자로서, 검색어 또는 대상 URL만 전송하여 전체 대화나 프로젝트 파일이 전달되지 않게 하고 싶다.
9. Cline 사용자로서, 검색 결과의 제목·URL·요약을 기본 5개 받아 읽을 출처를 선택하고 싶다.
10. Cline 사용자로서, 검색과 본문 조회를 따로 호출하여 필요한 페이지만 읽고 싶다.
11. Cline 사용자로서, 일반 공개 HTML 본문과 출처 URL을 받아 원문에 근거한 답변을 작성하고 싶다.
12. Cline 사용자로서, 긴 본문의 잘림 여부를 알아 반환된 내용이 전체 원문인지 판단하고 싶다.
13. Cline 사용자로서, 검색 결과가 없는 정상 응답과 검색 실패를 구분하여 잘못된 결론을 피하고 싶다.
14. Cline 사용자로서, CAPTCHA와 접근 차단을 명확한 실패로 받아 무인 검색이 중단된 이유를 알고 싶다.
15. Cline 사용자로서, 지원하지 않는 페이지의 사유를 받아 PDF나 로그인 페이지를 읽은 것으로 오해하지 않고 싶다.
16. Cline 사용자로서, 표준 출력의 JSON과 표준 오류의 진단을 분리하여 결과를 안정적으로 해석하고 싶다.
17. 내부망 PC 사용자로서, 인증 실패를 다른 오류와 구분하여 공유 토큰 설정을 바로잡고 싶다.
18. 내부망 PC 사용자로서, 서버가 처리 중이면 busy 응답을 받아 기다림 없이 현재 상태를 알고 싶다.
19. 내부망 PC 사용자로서, 요청이 30초로 제한되어 응답 없는 작업에 계속 묶이지 않고 싶다.
20. 내부망 PC 사용자로서, 실패 시 자동 재시도가 발생하지 않아 내가 요청한 범위 안에서만 서버가 동작하게 하고 싶다.
21. 인터넷 PC 운영자로서, Cline 없이 웹 중계 서버를 실행하여 독립적인 서비스로 운영하고 싶다.
22. 인터넷 PC 운영자로서, 서버와 전용 브라우저가 포함된 배포본을 받아 Python이나 개발 도구 설치 없이 시작하고 싶다.
23. 인터넷 PC 운영자로서, 실행 인자로 수신 주소·포트·공유 토큰을 지정하여 네트워크에 맞게 운영하고 싶다.
24. 인터넷 PC 운영자로서, 실행파일을 직접 시작하고 종료하여 필요한 동안만 서비스를 제공하고 싶다.
25. 인터넷 PC 운영자로서, 공유 토큰을 가진 클라이언트만 사용하게 하여 서버 접근을 제한하고 싶다.
26. 인터넷 PC 운영자로서, 공개 인터넷 주소만 조회하게 하여 서버를 통한 로컬·사내 주소 접근을 차단하고 싶다.
27. 인터넷 PC 운영자로서, 리다이렉트 대상에도 주소 제한을 적용하여 우회 접근을 막고 싶다.
28. 인터넷 PC 운영자로서, 검색 API 비용 없이 Google 헤드리스 검색을 사용하고 싶다.
29. 인터넷 PC 운영자로서, 요청 간 대화 이력을 유지하지 않아 각 요청을 독립적으로 처리하고 싶다.
30. 인터넷 PC 운영자로서, 애플리케이션에 검색어·본문·결과를 저장하지 않고 최소 운영 정보만 남기고 싶다.
31. 인터넷 PC 운영자로서, 정상 종료와 실패 시 브라우저 임시 데이터를 정리하여 요청 데이터가 계속 남지 않게 하고 싶다.
32. 인터넷 PC 운영자로서, 비정상 종료 잔여물을 다음 시작 시 정리하여 중단 이후에도 데이터 수명을 관리하고 싶다.
33. 인터넷 PC 운영자로서, 연결 종료 감지나 제한 시간 도달 시 브라우저 작업이 취소되어 다음 요청을 처리할 수 있게 하고 싶다.

## Implementation Decisions

- 구성 요소는 Cline 스킬, 표준 라이브러리 전용 Python 클라이언트, FastAPI 웹 중계 서버, 브라우저 기반 검색·본문 접근 계층, Windows 배포 패키지다. 현재 저장소에는 관련 애플리케이션 구현이나 기존 테스트 경계가 없다.
- 클라이언트는 Windows·Linux를 지원하며 Cline과 uv의 사전 설치 및 인터넷 차단 전 uv를 통한 Python 3.12 이상 준비를 요구한다. uv 실행 중 프로젝트 의존성 동기화나 Python·패키지 다운로드가 발생하지 않아야 한다. 오프라인 실행 옵션은 uv의 환경 준비를 제한하며 서버로 향하는 LAN 통신은 허용한다.
- 스킬은 프로젝트 루트를 명시적으로 전달하고 클라이언트는 그 루트의 환경 설정 파일만 읽는다. 서버 주소와 공유 토큰이 누락되면 설정 오류로 반환한다.
- 서버 설정은 실행 인자로 받는다. 필수 인증정보가 없을 때 인증 없이 시작하지 않는다. 첫 버전은 HTTP이며 전송 암호화를 제공하지 않는다는 운영 조건을 문서화한다.
- 서버는 Cline에 의존하지 않으며, Python 런타임과 전용 브라우저를 포함한 Windows x64 배포본으로 제공한다. 운영자가 직접 시작·종료한다.
- 서버는 유료 또는 무료 검색 API를 사용하지 않고 헤드리스 브라우저로 기본 검색엔진 Google에 접근한다. CAPTCHA·차단을 우회하거나 사용자의 개입을 기다리지 않고 해당 요청의 실패로 반환한다.
- 검색 요청의 업무 데이터는 검색어, 본문 조회의 업무 데이터는 대상 URL이다. 인증정보는 요청 인증에 사용하며 프로젝트 파일이나 대화 이력을 요청 데이터로 포함하지 않는다.
- 검색 응답은 기본 5개 결과의 제목·URL·요약을 제공한다. 실제 결과가 적으면 있는 결과만 반환하며 결과가 없으면 정상 빈 결과로 반환한다.
- 본문 조회는 일반 공개 HTML의 텍스트와 출처 URL을 반환한다. PDF, 로그인 필요 페이지, JavaScript 실행이 필요한 본문은 첫 버전에서 지원하지 않으며 확인 가능한 지원 불가 사유를 반환한다. Google 검색 화면을 위한 브라우저 실행과 본문 지원 범위는 구분한다.
- 본문은 최대 2만 자이며 초과 시 잘림 표시를 반환한다. 잘린 응답을 전체 본문으로 표현하지 않는다.
- 공개 인터넷 주소만 접근한다. 로컬·사내 IP와 해당 주소로 향하는 리다이렉트를 차단한다. 문자열 검사만으로 끝내지 않고 실제 연결 대상과 우회 경로에 같은 정책을 적용한다.
- 요청은 독립적이다. 한 번에 하나의 웹 작업만 처리하고 처리 중 새 요청은 대기열 대신 busy로 반환한다.
- 요청 처리 제한은 30초다. 클라이언트 연결 종료 감지 또는 제한 도달 시 작업을 취소하고 브라우저 자원을 정리한다. 클라이언트는 자동 재시도하지 않는다.
- 클라이언트 표준 출력은 JSON 결과이며 실행 진단은 표준 오류로 분리한다. 설정 오류, 연결 실패, 인증 실패, busy, CAPTCHA, 접근 차단, 시간 초과, 주소 정책 위반, 지원 불가를 구별 가능한 오류로 표현한다. 구체적인 필드명과 HTTP 경로는 구현 시 일관된 계약으로 정의한다.
- 애플리케이션은 검색어·본문·결과를 영속 저장하지 않는다. 운영 로그는 처리 시간·성공·실패 같은 최소 정보로 한정하며 인증 토큰도 출력하지 않는다.
- 브라우저 임시 프로필·캐시의 실행 중 디스크 기록은 허용한다. 요청 종료·실패 시 삭제하고 비정상 종료 잔여물은 다음 서버 시작 시 정리한다. Statelesness는 실행 중 디스크 기록 자체가 전혀 없다는 뜻이 아니다.

## Testing Decisions

- 사용자가 승인한 첫 버전 완료 기준을 검증 대상으로 삼는다. 좋은 테스트는 호출자가 관찰하는 결과, 실패 구분, 제한 시간, 네트워크 접근 정책, 데이터 정리 상태를 검증한다. 내부 함수 호출 순서나 특정 DOM selector를 그대로 복제한 테스트는 완료 근거로 삼지 않는다.
- 주 검증 경계는 공개 클라이언트 호출에서 실제 서버를 거쳐 반환되는 JSON·오류까지다. 스킬의 Cline 호출 흐름과 패키지 실행은 플랫폼별 수용 검증으로 보완한다. 애플리케이션 테스트의 기존 사례나 재사용 가능한 구현 경계는 현재 저장소에 없다.
- 반복 가능한 통합 검증에서는 외부 웹 경계에 통제된 검색·페이지 응답을 제공한다. 검색 성공·빈 결과·CAPTCHA·차단·비HTML 응답·리다이렉트·느린 응답·긴 본문을 재현하되, 클라이언트와 서버의 공개 계약은 실제 경로로 실행한다.
- Google 실검색 성공과 공개 HTML 본문 조회를 별도 라이브 검증한다. 통제된 응답의 성공만으로 실제 검색 성공을 선언하지 않으며 CAPTCHA 발생도 검색 성공으로 간주하지 않는다.
- Windows·Linux에서 Cline이 스킬을 통해 검색과 선택한 URL의 본문 조회에 성공하는 것을 검증한다. 사용한 Cline·Python·uv 버전과 운영체제를 증거에 기록한다.
- 외부 인터넷에 접근할 수 없는 클라이언트 환경에서 LAN 서버 요청만으로 동작하고 패키지·Python 다운로드가 발생하지 않는지 확인한다. 명시한 프로젝트 루트 밖의 설정이 사용되지 않는지도 검증한다.
- Cline·Python이 별도 설치되지 않은 Windows x64 환경에서 배포 폴더의 서버 실행파일과 번들 브라우저만으로 시작·검색·본문 조회·종료에 성공하는지 확인한다.
- 누락된 설정과 잘못된 토큰은 구별 가능한 오류로 반환한다. 동시 요청은 하나만 처리하고 나머지는 busy를 반환한다.
- CAPTCHA·접근 차단·시간 초과·지원 불가를 정상 빈 검색 결과와 구분한다. 클라이언트 실패 시 자동 재시도가 없는지 검증한다.
- 로컬·사내 IP 및 해당 주소로 향하는 리다이렉트가 차단되는지 검증한다. 호스트 이름이 비공개 주소로 해석되는 경우와 주소 표현 변형도 같은 공개 접근 정책으로 다룬다.
- 본문 2만 자 경계와 잘림 표시, 출처 보존을 검증한다.
- 연결 종료·시간 초과·성공·실패 이후 브라우저 작업과 임시 데이터가 정리되고 다음 요청이 처리 가능한지 확인한다. 강제 종료 후 다음 시작에서 잔여물 정리도 확인한다.
- 검색어·본문·결과·토큰이 애플리케이션 로그나 영속 데이터에 남지 않는지 확인한다. 요청 중 허용된 브라우저 임시 데이터와 요청 후 정리 상태를 구분한다.

## Out of Scope

- macOS 클라이언트, Windows x64 이외 서버 배포.
- 인터넷 PC에서 Cline 실행, 서버 측 LLM 요약·답변 생성, 대화 세션 보관.
- 검색 API 사용, 유료 검색 서비스, 다중 검색엔진 자동 전환.
- CAPTCHA 우회·사람의 CAPTCHA 해결 흐름·무조건적인 검색 성공 보장.
- PDF, 로그인 페이지, JavaScript 실행이 필요한 본문 조회.
- 프로젝트 파일·전체 대화 전달, 사내·로컬 페이지 조회.
- HTTPS 인증서 배포, Windows 서비스 등록, 다중 사용자 계정 관리.
- 병렬 웹 작업, 요청 대기열, 자동 재시도, 검색 결과의 영속 캐시.
- 실행 중 브라우저 임시 디스크 기록까지 전면 금지하는 환경.

## Further Notes

- 사용자가 2026-09-08 전체 설계와 첫 버전 완료 기준을 확정했다. 이 이슈는 구현을 위한 명세이며 이미 구현되었거나 검증되었다는 보고가 아니다.
- 현재 저장소에는 설정 문서와 스킬 자산이 있으며 애플리케이션 코드와 테스트는 아직 없다. 구현 언어·프레임워크 선택 중 확정 사항은 클라이언트 Python/uv와 서버 FastAPI다. 브라우저 제어·패키징 도구의 구체적인 선택은 위 동작과 배포 계약을 충족하도록 구현 시 결정한다.

- 명세 게시 및 ready-for-agent 지정은 승인되었으며, 이번 작업에서 구현이나 배포를 실행하지 않는다.
